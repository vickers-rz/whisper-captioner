# Gemini YouTube 多模态 A/B 实验

## 实验对象

- 视频：`https://www.youtube.com/watch?v=LGSJs6QLZDQ`
- 时长：`2905.148s`（约 48 分 25 秒）
- 模型：`gemini-3.5-flash`
- A 组：公开 YouTube URL 直接作为 Gemini 视频输入
- B 组：已下载 OGG 的 Gemini 2.5 Flash 全文转写
- 时间基线：Gemini 全文对齐 NUC Whisper words 后的 `asr.json`
- 字幕状态：YouTube 页面未发现可用字幕；API 内部是否参考字幕不可知，本实验不依赖这一假设

## 结论

公开 YouTube URL 可以被 Gemini API 直接读取，并能从同一次视频输入中提取音频语义、章节、实体、画面事件和 OCR。它适合做多模态内容理解，但不适合直接替代当前 ASR 和字幕时间轴。

推荐最终组合：

1. OGG + Gemini：高质量完整全文。
2. NUC Whisper words：精确词级时间戳。
3. YouTube URL + Gemini：章节、画面事件、OCR、视觉证据和专名候选。
4. 将第 3 项全部重新对齐到第 2 项，不采用 Gemini 自报时间戳。

## 实验一：整段多模态结构

低媒体分辨率整段调用成功：

- 输入：247,149 tokens，其中视频 246,928
- 输出：6,566 tokens
- 耗时：159.295s
- 结果：6 个章节、24 个视觉事件、13 个核心主张、22 个实体

模型识别了片头标题、历史影视素材、新闻画面、人物照片、广告、二维码、外卖员素材和章节标题卡。但结构结果只覆盖到 `2546s`，比实际结尾少 `359s`；其中若干视觉事件时间也明显错误。例如整段结果把 Saily 广告标在约 `1047s`，实际音频时间在约 `625–788s`，而 `1047s` 附近是就业和农民工论述。

因此，整段结构的内容描述可作候选，时间戳必须重新对齐。

## 实验二：单次整段语义转写

虽然 API 状态为 `completed`，实际只转写到 `495s`：

- 21 个 segment
- 仅覆盖前 8 分 15 秒
- 相对 OGG Gemini 全文的字符覆盖率：10.93%
- 候选文本匹配精度：99.01%

`completed` 只代表生成正常停止，不代表满足“完整转写”。必须增加时长和文本覆盖检查。

## 实验三：8 分钟分片转写

使用原生 `video_metadata.start_offset/end_offset`，共 7 个分片。每个完整 8 分钟片段输入约 40,800 个视频 tokens，证明服务端确实执行了媒体裁剪。

- 146 个 segment，表面时间轴覆盖到 `2905.148s`
- 候选文本长度为 OGG Gemini 全文的 75.35%
- 基线字符覆盖率：74.04%
- 候选文本匹配精度：98.26%
- 相对 NUC 融合时间轴的时间误差中位数：53.96s
- P90 时间误差：125.74s
- 最大时间误差：172.22s

主要问题是模型会省略片段后半段的措辞，却仍把剩余文本的时间戳均匀铺满整个 8 分钟。数字时间轴连续，但内容时间轴不连续。

## 实验四：2 分钟分片控制组

只测试前 8 分钟，拆成四个 2 分钟片段：

- 时间误差中位数降至 7.30s
- P90 时间误差降至 30.51s
- 最大时间误差降至 42.20s
- 四段字符覆盖率分别为 69.59%、63.81%、94.50%、81.05%
- 前 8 分钟整体匹配覆盖约 77.11%

短窗口显著改善时间定位，但仍会遗漏文本。继续缩短到 30 秒或更短会增加大量请求、成本和边界处理复杂度，收益不如保留 NUC Whisper 时间轴。

## 实验五：高分辨率视觉定点读取

对 `1020–1120s` 做高分辨率视觉检查：

- 输入：29,081 tokens，其中 23,086 为缓存 tokens
- 输出：1,963 tokens
- 耗时：12.775s
- 正确读取画面叠字，包括“当前中国的 TFP 损失”“中国 2.81 亿农民工”“官方公布的青年失业率长期维持在 20% 左右”
- 正确识别办公室、工厂、失业者、外卖员等画面只是 `illustrative`
- 没有把装饰性 B-roll 判定为事实证据

这说明“低分辨率整段扫描 + 对关键窗口高分辨率复查”是有效且更经济的用法。

## 数据质量注意事项

- `visually_resolved_terms` 输出了 71 个术语，但其中很多也能从音频获得，不能直接认定为视觉纠错成果。
- OCR 文本只能作为候选，需与邻近音频、NUC 文本或截图复核。
- Gemini 视频时间戳只用于搜索附近窗口，不能直接生成 SRT。
- 本报告的时间误差以现有 NUC 融合时间轴为参照，不是人工逐帧真值，但已经足以识别分钟级漂移。
- 视频中的影视素材和库存画面通常只是修辞性配图，不构成对口播事实主张的独立证明。

## 建议集成规则

1. 默认不让 URL 视频通道生成全文字幕。
2. 先用整段低分辨率调用提取章节、画面事件和待核查主张。
3. 对图表、引用、二维码、人物标签和数据画面进行 60–120 秒高分辨率定点调用。
4. 所有视觉事件通过文本相似度和 NUC words 重新落到准确时间轴。
5. 视觉证据明确区分 `visual_only`、`supports_audio` 和 `illustrative`。
6. 加入覆盖检查：末章必须到达视频结尾，事件时间必须经 NUC 或定点复核。
7. 保留现有 OGG 回退路径，以处理 URL 预览能力、地区限制或公开视频不可访问的问题。
