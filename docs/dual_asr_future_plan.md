# 下一阶段：Whisper + Gemini 双模型字幕融合

## 状态

本计划仅作为下一阶段设计记录。当前阶段不实现、不注册，也不添加 UI 控件。
未来模式名暂定为 `dual_asr_precision`。

## 首选设计

- faster-whisper 提供逐词时间轴、声学置信度和 speech coverage 主干。
- 在线 Gemini 读取完整音频，提供长上下文文本、专名和疑似漏句候选。
- 两路并行执行并独立缓存：NUC 运行 faster-whisper，Mac 调用 Gemini API。
- 通过 token 序列对齐识别一致区、冲突区和单路新增文本。
- 冲突区批量执行局部复核，避免逐句重复调用。
- Gemini 新增文本必须经过强制对齐后才能进入最终时间轴。
- 不采用 Gemini 自报时间戳作为最终时间轴；它只能作为粗定位提示。
- 未解决冲突保存双候选及证据，不交给普通 LLM 猜测。
- 融合后的 speech coverage 不得低于任一单模型结果。
- 普通 LLM 润色仍只能修改文本，不得改变 segment 数量、顺序或时间戳。

## 离线备选

- Qwen 保留为无云端上传、无 Gemini key 或隐私敏感场景的文本候选。
- Qwen 与 Gemini 使用相同的 token 对齐、冲突记录和强制对齐约束。
- Gemini 失败、限流或超时时自动回退当前单模型闭环，不阻断字幕生成。
- Gemini 与 Qwen 候选缓存不可互相冒充，缓存签名必须包含模型和提示词版本。

## 研究依据

- Gemini 音频转录文本准确率很高，但其生成式时间戳不能作为逐词事实来源。
- 强制对齐是双模型融合的必要环节，但 LattifAI 经实测质量不满足需求已放弃；
  后续需寻找替代对齐方案或自研。
- Gemini API 的音频上传、隐私提示、费用、限流和失败回退必须在 UI 中明确。

## 暂不实现

当前阶段禁止：

- 在 `MODES` 中注册 `dual_asr_precision`。
- 实现融合评分器、`FusionDecision` 或生产融合逻辑。
- 添加双模型 UI 控件。
- 为双模型修改当前 NUC 调度流程。
- 让 Gemini 或 Qwen 新文本绕过强制对齐进入字幕。

## 后续研究

- token 对齐对中英混合、繁简体和专名变体的归一化规则。
- 冲突置信度、声学证据与上下文证据的可解释评分。
- 双模型局部复核批处理和缓存失效边界。
- Gemini 模型选择、温度、thinking、URL 与本地音频输入的可重复基准。
- Gemini API 成本、音频缓存和用户明确同意上传的交互。
- 对齐服务不可用时双候选的人工审核工作流。
- 说话人分离、说话人标签稳定和跨段 speaker continuity。

说话人分离与双模型融合分别设计和验收，不在同一阶段同时引入。
