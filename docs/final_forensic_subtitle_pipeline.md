# 最终字幕取证与生成流程

## 目标

生成一份可审核的高质量字幕：本地 NUC ASR 先生成带词级时间戳的 JSON 和
初始 SRT，固定声学时间轴；Gemini 全文只回填该 SRT 的文字和标点，不改变其
时间。若视频含烧录硬字幕，则 OCR 只对文字分歧进行裁决，绝不参与时间轴
校正。最终由确定性断句算法重新分段，再从 NUC 词级时间戳重建新的句级时间轴。

## 证据层与职责

| 层 | 产物 | 唯一职责 | 不负责 |
| --- | --- | --- | --- |
| NUC 本地 ASR | 高精度 `*-asr.json` 和初始 SRT，含 `words[].start/end` | 固定声学词级/句级时间轴、停顿与说话节奏 | 最终错字、专名裁决 |
| Gemini ASR | OGG 输入得到的无时间轴全文转写 | 回填本地 SRT 的文字、标点和专名 | 改写或重定本地时间轴 |
| 硬字幕 OCR | 有硬字幕画面的局部文字 | 对明确分歧做视觉文字裁决 | 时间锚定、补全未显示在画面的语音 |
| 断句算法 | 标点、字数、阅读速度、NUC 词级停顿 | 可复现的字幕断句 | 修改、补写、删减正文 |

## 流程

0. **低成本预检是否存在烧录硬字幕**
   - 不下载完整视频。先用 `yt-dlp --download-sections` 获取若干低分辨率、短时间
     片段；`yt-dlp` 负责取得视频流，实际按指定时间取帧由 FFmpeg 完成。
   - 在开头、约 10%、30%、50%、70%、90% 和结尾附近抽样；每个窗口取 3 至 5
     帧，并在常见字幕区域（下方横带）运行轻量 OCR。
   - 当多个分散窗口连续检测到位置稳定、OCR 置信度足够的文字时，标记为
     `burned_subtitles_present`；否则标记为 `not_detected`，跳过第 4 步。
   - 只有判定 `burned_subtitles_present` 后，才按第 3 步的争议时间窗口下载对应的
     较清晰短片段，执行精细 OCR；全片视频下载不是 OCR 流程的前置条件。
   - `not_detected` 只是“抽样未发现”，不能证明全片没有硬字幕。对只在局部出现
     字幕的视频，可在后续人工复核或异常争议密集区追加一次采样。

1. **获得高精度词级 ASR JSON 和初始 SRT**
   - 下载/提取音频，使用 NUC ASR 输出 `words`、`segments` 和置信度。
   - 同时由本地 ASR 生成初始 SRT。该 SRT 的时间与 `words[].start/end` 是后续
     流程的固定声学基线，必须保留原始 JSON 与原始 SRT。

2. **将 OGG 提交 Gemini 做无时间轴全文 ASR**
   - 将 `webm/opus` 转为 `ogg/opus`，通过 Gemini File API 取得完整转写。
   - Gemini 全文只作为文字模板：保留标点、专名、修辞和长句上下文，不要求、
     不采用 Gemini 的任何时间信息。

3. **以 Gemini 全文回填本地 ASR SRT 的文字**
   - 将 Gemini 全文与本地 ASR SRT 做单调字符/词对齐；以本地 SRT 每条的原有
     起止时间和顺序为约束，仅替换该条中的文字、标点、专名或漏识别内容。
   - 此步骤不得新增、删除、重排 SRT 条目，也不得改变任何起止时间；产物是
     “Gemini 回填文字 + 本地 ASR 原时间轴”的中间 SRT。
   - 以原始本地 ASR 文本与 Gemini 回填文本的具体差异生成争议清单，并继承其
     所在本地 SRT 条目的时间窗口，供下一步按需 OCR 使用。

4. **按需 OCR 裁决文字分歧**
   - 先确认视频确有烧录硬字幕；无硬字幕时跳过本步。
   - 不做无目的全片高频 OCR。按第 3 步的分歧时间窗反向规划取帧：
     短窗口密采样，长窗口在边界密采样、内部稀采样。
   - OCR 的原始文字、置信度、帧图和取样计划必须保存，不能只保留融合后的结果。
   - OCR 明确支持 Gemini 或本地 ASR 某一写法时，才应用该文字修正。
   - OCR 证据不足、截断或置信度低时，保持 Gemini 模板，不把“未证明”视为反证。
   - OCR 不参与时间轴校正，也不以帧时间覆盖 NUC ASR 的词级时间。它仅修改
     已定位争议位置的文字。

5. **以确定性算法进行全文断句**
   - 输入是 Gemini 回填并经 OCR 裁决后的最终正文，而不是逐条 OCR cue。
   - 仅在已有字符边界断开，优先级为：句末标点（`。！？；`）、分句标点
     （`，、：`）、NUC 词级长停顿、字数和阅读速度约束。
   - 目标是每条字幕具有合理的最短/最长时长、字数与阅读速度；候选边界不足时
     才在词边界拆分，绝不改写、增删或重排正文。
   - 算法输出必须可复现，并验证所有 cue 串接后与已裁决正文逐字符一致。
     
6. **将算法断句映射回时间轴并生成字幕**
   - 对每个断句，从原始 NUC `words` 取首词开始、末词结束；在 Gemini 新增或替换
     字符附近，以相邻已对齐 NUC 词做单调插值，但不得引入 OCR 帧时间。
   - 加入显示约束：时间单调、无重叠、合理的最短/最长时长、每条适中的字数与
     阅读速度；必要时仅在算法选定的词边界处分成两条。
   - 输出 SRT 作为播放交付，同时输出 JSON 作为无损审计产物。

## 决策规则

- **文字优先级**：OCR 明确裁决 > Gemini 全文模板 > NUC ASR 原文。
- **时间优先级**：NUC `words` 声学时间 > 相邻已对齐词的单调插值；OCR 不参与。
- **断句优先级**：明确句末标点 > 分句标点 > NUC 词级停顿 > 字数/阅读速度规则。
- **安全底线**：任何模型均不得静默改变最终正文；所有文字改动、OCR 裁决、
  NUC 词级时间映射和算法断句决策都必须可追溯。

## 交付物

- `nuc-word-asr.json`：原始本地词级时间证据。
- `gemini-transcript.txt`：原始 Gemini 全文证据。
- `gemini-backfilled-local-timeline.srt`：Gemini 回填文字、但完全保留本地时间的中间字幕。
- `transcript-differences.json`：原始本地 ASR 与 Gemini 回填文本的差异及本地 SRT 时间窗口。
- `targeted-ocr-plan.json`、`ocr-raw.jsonl`：按需 OCR 的计划与原始证据。
- `ocr-adjudications.json`：每项分歧的裁决、置信度和理由。
- `final-timeline.json`：最终正文、字符/词映射、时间和算法断句审计。
- `final.srt`：面向播放的最终字幕。
